the session: it asks the KLP platform who is signed in, keeps the session alive while the user is
active, and receives unread messages and sign-ins or sign-outs from other tabs as they happen. Your
application only provides the links.

## Environment

The `environment` property selects the KLP platform the widget talks to, and with it every URL the
widget calls: `prod` uses `n.account.post.ch`, the other environments use the matching test
platforms. Your page's origin has to be on that platform's allowlist, and the page has to be served
from a `post.ch` domain, so the session cookie is sent along.

If your page uses a Content Security Policy, allow the platform in `connect-src`, for both `https:`
and `wss:`, because the widget also opens a websocket to it.

## Links

All links are provided by your application, as light DOM in the widget's slots. The widget decides
which of them to show:

| Slot             | Content                                           | Shown                                               |
| ---------------- | ------------------------------------------------- | --------------------------------------------------- |
| `login-link`     | A link to the login page.                         | To anonymous visitors.                              |
| `account-switch` | A `post-menu-item` linking to the account switch. | When the session allows the user to switch account. |
| `company-switch` | A `post-menu-item` linking to the company switch. | When the session allows the user to switch company. |
| `menu-links`     | Any number of `post-menu-item` elements.          | In the user menu, in the order given.               |
| `logout-link`    | A `post-menu-item` linking to the logout.         | Last in the user menu.                              |

The account switch and the company switch are never shown together.

## Unread messages

Place a `post-klp-login-widget-messages` element among the `menu-links`, wherever the messages entry
should appear. It shows the number of unread messages the platform reports, and the avatar shows a
dot as long as there are any. Both update as messages arrive, without a reload.

| Attribute     | Description                                                                 |
| ------------- | --------------------------------------------------------------------------- |
| `url`         | Where the entry points.                                                     |
| `text`        | Label of the entry.                                                         |
| `text-unread` | Visually hidden label for the count. `{count}` is replaced with the number. |

## Before the session is known

Until the platform has answered, the widget reserves an avatar-sized box, so the header does not
shift once the session is known. If your page already knows the visitor is anonymous, set
`initial-state="anonymous"` to render the login link right away.

## Accessibility

The avatar has no visible label, so the widget relies on three texts, which must be translated
into the page's language:

- `text-current-user` describes the avatar; `{user}` is replaced with the user's full name.
- `text-access-user-links` is the accessible name of the button opening the user menu.
- `text-user-links` labels the user menu itself.

Give the messages entry a `text-unread` as well, since its count is otherwise announced as a bare
number.
