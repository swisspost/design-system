# Collapsible

<StoryTags meta={meta} />

<p className="lead">The collapsible toggles the visibility of content within your project.</p>

The `<post-collapsible>` component is used to show and hide content.
Using a trigger or the `toggle()` method animates the height when opening or closing.

## Examples

The following examples show different use cases for the `<post-collapsible>` component.

### Initially Collapsed

To make the collapsible content hidden by default, just use the `collapsible="true"` property.

<Canvas of={CollapsibleStories.InitiallyCollapsed} />

### Findable Content

Set `findable` to allow deeplinking and browser search to open a closed collapsible.
This option defaults to `false`.
A link to `#findable-collapsible-content` opens the example below.

<Canvas of={CollapsibleStories.Findable} />

Browser search uses [`hidden="until-found"`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/hidden#the_hidden_until_found_state) where supported.
A fallback for deeplinking is provided for browsers not supporting `hidden="until-found"`.
A match opens collapsibles immediately and emits the `postToggle` event with `true`.
For nested collapsibles, all findable ancestors also open to make the matched content visible.

### Programmatic Toggle

The `<post-collapsible>` component offers a `.toggle()` method that allows you to trigger the collapse programmatically.
This method is asynchronous and returns a promise that resolves with the current open state.
It optionally takes a boolean parameter: `true` forces it open, and `false` forces it closed.

When connected in a browser, `toggle()` animates the state change and emits `postToggle` before the animation.
Calling it with the current state does nothing.
On a disconnected element, it updates the state without animation or a `postToggle` event.

Setting the `collapsed` property directly updates visibility without animation and does not emit `postToggle`.
Use `toggle()` for animated changes.

### Wrapped Collapsible

The `<post-collapsible>` can be nested within the `<post-collapsible-trigger>` to establish the trigger–collapsible relationship, eliminating the need for an explicit id reference.
