<post-tab-panel for="client-side-routing" class="pt-24">

To enable client-side routing (e.g. Next.js, Angular Router), slot your own anchor instead of using the `url`/`home-url` properties: use the default slot for `<post-breadcrumb-item>`, or the `home` slot for the root item of `<post-breadcrumbs>`.

Both components detect the slotted `<a>` and stop rendering their own, leaving your link's click handling untouched.

<post-banner type="info">
  <p>
    The slotted `<a>` must be a direct child of `<post-breadcrumb-item>` (or of `<post-breadcrumbs>`
    for the `home` slot), not wrapped in another element, otherwise it won't be detected and the
    component will fall back to rendering its own internal link.
  </p>
  <p>
    The `url`/`home-url` properties are ignored once you slot your own `<a>`. Since the label,
    description, and `aria-current` are no longer applied automatically, give the slotted `<a>`
    an accessible name (via its text content or `aria-label`), and add `aria-current="page"`
    yourself on the item that represents the current page.
  </p>
</post-banner>

<post-tab-panel for="home-text" class="pt-24">

By default, the root breadcrumb displays a home icon and uses `text-home` as its accessible label. It is also possible to hide the icon and show text in its place, which is useful when the root breadcrumb should link to a segment-specific home page, such as "Private customers" or "About us", rather than the generic site root. There are two ways to do this, depending on how the home link is implemented.

With the <b>default routing behavior</b>, set `home-text-only` to `true`. The component hides the icon and displays the `text-home` content instead.

When using <b>client-side routing</b>, `home-text-only` has no effect because the home link is provided through the `home` slot. Slot a direct `<a>` element with visible text and omit the `<post-icon>`; the component detects the slotted anchor without an icon and renders it as the text-only home item.
